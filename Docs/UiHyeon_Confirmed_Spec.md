# 의현 담당 확정 사양

> 상태: 1차 답변 반영  
> 범위: 플레이어 플레이 기능, 공통 시드 모듈

## 1. 개발 환경과 대상

- Unity 6000.3.18f1, URP
- Windows PC 단독
- 키보드와 마우스만 우선 지원
- 게임패드와 키 리바인딩은 이후 범위
- 플레이어 기본 데이터와 직업별 데이터는 ScriptableObject로 분리
- 원본 데이터와 런타임 상태를 분리
- XML 문서와 주석은 한국어 사용
- 다른 개발자의 코드 영역과 Assembly Definition을 침범하지 않음
- 커밋은 반드시 사전 보고 후 사용자 승인을 받아 진행

## 2. 카메라와 공간

- 쿼터뷰
- 정면 기준 약 45도 위에서 내려다보는 구도
- Cinemachine Orbital 계열 카메라 사용 예정
- 참고 게임: Vampire Survivors, 모험가 엘리엇의 천 년 이야기
- 기본 이동면은 3D XZ 평면
- 점프와 플레이어의 능동적인 높낮이 이동 없음
- 맵 지형에는 굴곡이 존재할 수 있으므로 스킬 범위와 투사체는 지형 높이를 고려

## 3. 플레이어 표현

- 초기에는 3D Capsule 사용
- 추후 카메라를 항상 바라보는 Sprite로 교체
- Sprite는 조준 방향에 따라 좌우 반전
- 정식 캐릭터·애니메이션·이펙트 에셋은 아직 없음
- 기능 검증 단계에서는 Capsule, Cube, 단색 이펙트 사용

## 4. 이동

- CharacterController 사용
- WASD 입력 즉시 최고 속도
- 대각선 입력 정규화
- 캐릭터의 전투 방향은 조준 방향
- 적이나 다른 대상을 물리적으로 밀지 않음
- 일반 이동 중 공격과 스킬 사용 가능
- 공격 중 이동 속도 감소 없음

## 5. 대시

- 입력: Space
- 현재 이동 입력 방향으로 대시
- 이동 입력이 없으면 사용 불가
- 순간이동이 아닌, 약 0.2~0.3초 동안 짧은 거리를 매우 빠르게 이동하는 방식
- 대시 중 방향 전환 불가
- 대시 전체 시간 동안 무적
- 적을 통과할 수 있음
- 벽에 닿으면 이동 거리는 막히지만 남은 대시 시간과 무적은 유지
- 대시 중 기본 공격과 액티브 스킬 사용 가능
- 대시 공격은 일반 공격과 별도 규칙으로 추후 구현
- 기본 충전 수 2회
- 각 충전은 대시 전용 쿨타임으로 회복
- 스킬 쿨타임과 대시 쿨타임 수치를 분리
- 정확한 거리, 속도, 지속 시간은 테스트 후 조정

## 6. 조준과 기본 공격

- 기본 공격은 자동으로 계속 발동
- 플레이어 공격 범위 안의 가장 가까운 적을 자동 조준
- 공격 범위가 화면 밖까지 닿으면 화면 밖 대상도 조준 가능
- 좌클릭을 누르는 동안 마우스 월드 좌표 방향으로 수동 조준
- 좌클릭을 놓으면 자동 조준으로 복귀
- 전사의 기본 공격은 전방 근접 검 공격
- 초기 기본 공격 범위: 플레이어 전방 1.5m
- 공격 중 이동 가능
- Sprite 전환 후 조준 방향은 좌우 반전으로 표현

## 7. 액티브 스킬 조작

- 기본 방식: 우클릭을 누르는 동안 조준하고, 버튼을 놓을 때 발동
- 추후 환경설정에서 스마트키 방식 지원
- 스마트키 방식: 우클릭을 누르는 순간 현재 방향으로 즉시 발동
- 조준 중 좌클릭이 눌려 있으면 수동 조준 방향을 계속 사용
- 스킬 사용 중 이동과 대시 가능
- 애니메이션 취소 규칙은 현재 제외하되 확장 가능한 구조 유지

## 8. 전사 액티브 — 검기

- 직선 투사체
- 한 번의 스킬 사용으로 검기 3발 발사
- 3발은 같은 방향과 같은 크기로 일정한 발사 간격을 두고 순차 발사
- 적 관통
- 최대 10개 대상 적중
- 벽과 충돌하면 소멸
- 기본 시전 시간 0.2초 후 첫 검기 발사 시작
- 시전 시간은 0초, 1초 등 데이터로 변경 가능하게 구성
- 초기 투사체 속도는 테스트에 적합한 임시값으로 설정 후 조정
- 검기 가로 폭은 플레이어 너비의 약 2배
- 후딜레이는 기본 공격 주기를 기준으로 사용
- 기본 쿨타임 10초
- 첫 구현에서는 속성 효과 제외
- 추후 속성별로 별도 스킬이 될 가능성을 고려해 스킬 데이터와 실행 로직 분리

## 9. 생존

- 전사 기본 최대 HP: 50
- 피격 직후 무적 시간: 0.3초
- 일반 피격에는 넉백, 경직, 화면 흔들림 없음
- 특정 보스 패턴용 넉백·경직·화면 흔들림은 이후 확장
- HP가 0이 되면 즉시 사망
- 현재 사망 책임: 입력 정지와 사망 이벤트 발생
- 추후 부활을 추가할 수 있도록 사망과 최종 런 종료를 분리
- 낙사 없음

## 10. 능력치

- 능력치는 실수형을 기본으로 사용
- 플레이어 관련 전체 능력치가 대상
- 투사체 수·속도·크기는 전사의 액티브 스킬에 적용
- 공격 속도와 쿨타임 관련 증감값은 기본값 대비 -70%~+70%로 제한
- 쿨타임 감소 최대치는 70%로 제한하여 최소 쿨타임은 원본의 30%
- 정확한 피해 계산식은 미정
- 치명타, 회피, 피해 감소 계산 순서는 미정

## 11. 일시정지와 입력 차단

- ESC 일시정지 필요
- `Time.timeScale = 0`으로 게임 정지
- 이동, 공격, 스킬, 대시, 일반 쿨타임도 함께 정지
- 일시정지, 레벨업 보상, 아이템 선택, 노드 지도 등 게임플레이 UI가 열리면 플레이어 입력 차단
- UI 전용 입력은 계속 허용

## 12. 시드 기본 규칙

- 사용자 입력 시드는 숫자 6자리
- 난수 알고리즘은 프로젝트에 고정한 MT19937 메르센 트위스터 사용
- 마을의 디버그 UI에서 직접 입력 가능
- 빈 값이면 무작위 시드 생성
- 시드 표시와 복사 UI도 의현 담당
- 마을에 처음 진입할 때 새 시드 생성
- 던전 성공 또는 실패 후 마을로 돌아올 때 새 시드 생성
- 디버그 모드에서 직접 입력한 시드는 다음 던전에 사용
- 던전 입장 후에는 해당 런 시드를 변경하지 않음
- 동일 시드는 시드 알고리즘 버전과 콘텐츠 데이터 구성이 같다면 Unity 버전 및 게임 업데이트 후에도 같은 결과를 보장
- Unity 또는 .NET 내장 난수 구현에 결과를 의존하지 않음
- 치명타와 상태 이상 부여 확률 같은 전투 중 확률 판정은 런 시드 대상에서 제외
- 콘텐츠 배치와 선택 결과에 사용하는 랜덤은 런 시드 대상
- 스트림 이름은 고정 열거형이 아니라 확장 가능하게 설계
- 시스템별 독립 MT19937 스트림 안에서는 순서 의존형으로 값을 소비
- 실제 맵·몬스터·아이템 등에 시드를 연결하는 작업은 각 담당자가 수행

## 13. 테스트 환경

- 경로: `Assets/Scenes/NUH`
- 첫 테스트 씬 이름 후보: `Test_01_PlayerBase`
- 이후 형식: `Test_02_기능명`, `Test_03_기능명`
- 단계별로 사용자 확인을 받은 후 다음 단계 진행
- 플레이어 테스트 전용 DummyTarget과 DamageZone 허용
- 테스트 UI 확정 기능:
  - 능력치 변경
  - 무적 On/Off
  - 씬/플레이어 재시작
  - 액티브 스킬 쿨타임 제거 On/Off
- 추가 테스트 기능은 구현 전 사용자 승인 필요

## 14. 추가 전투 규칙

- 대시 충전 2회는 하나씩 순차적으로 회복
- 자동 공격은 공격 범위 안에 대상이 없으면 발동하지 않음
- 좌클릭 수동 공격은 대상이 없어도 현재 조준 방향으로 발동

## 15. 데이터 관리 권장안

플레이어는 **ScriptableObject + 런타임 복사본** 조합을 권장한다.

- ScriptableObject: 직업의 변하지 않는 원본값과 에디터 튜닝값
- 런타임 객체: 현재 HP, 쿨타임, 임시 증감값, 런 중 변화
- CSV: 대량의 행을 일괄 편집·비교해야 할 때 유리하지만, 현재 플레이어 직업 수와 데이터량에는 과함

ScriptableObject 원본을 플레이 중 직접 수정하면 에디터에서 값이 남거나 여러 객체가 상태를 공유할 위험이 있다. 따라서 런 시작 시 원본을 런타임 상태로 복사하고, 게임 중에는 복사본만 변경한다. 직업 수와 스킬 수가 크게 늘면 CSV를 원본 데이터 입력 수단으로 추가하되, 런타임 구조는 그대로 유지하는 편이 안전하다.
