# 의현 작업 로드맵 — 플레이어와 시드 시스템

> 목표: 의현 담당인 **플레이어 플레이 기능**과 **공통 시드 시스템** 자체를 완성한다. 다른 담당 시스템과의 연결 및 통합은 의현의 작업 범위에 포함하지 않는다.

구현 세부값은 [의현 담당 확정 사양](./UiHyeon_Confirmed_Spec.md), 시드의 미결정 사항은 [시드 설계 결정 가이드](./Seed_Design_Decisions.md)를 기준으로 한다.

## 1. 담당 범위

### 의현이 구현할 것

- 플레이어 이동과 대시
- 카메라와 조준
- 기본 공격
- 직업 액티브 스킬
- 플레이어 능력치, HP, 피격, 사망
- 공격 및 스킬의 피해 전달
- 입력 시스템
- 런 전체가 공유하는 시드와 난수 API
- 시드 재현 확인용 디버그 기능
- 추가 직업의 플레이 기능(한 사이클 안정화 이후)

### 다른 담당자가 구현할 것

- 맵, 방, StageManager, 노드 지도
- 일반·엘리트·보스 몬스터
- 인벤토리, 아이템, 속성, 시너지
- 세이브/로드
- 업적과 영구 특성
- 상점, 제련소, 이벤트 등 콘텐츠
- 몬스터와 플레이어의 연결 작업
- 아이템과 플레이어의 연결 작업
- 각 콘텐츠에 시드 시스템을 연결하는 작업

의현은 위 시스템의 구현뿐 아니라 연결 작업도 맡지 않는다. 플레이어와 시드를 시험하기 위해 꼭 필요할 때만 의현 전용 임시 테스트 오브젝트를 사용하며, 이를 정식 연동 코드로 발전시키지 않는다.

## 2. 전체 사이클 중 의현의 산출물

```text
플레이어 모듈
→ 이동·대시·카메라
→ 기본 공격·조준·직업 스킬
→ 능력치·HP·피격·사망

시드 모듈
→ 런 시드 생성·등록
→ 독립 난수 스트림 생성
→ 동일 시드 결과 재현
```

다른 담당자가 이 산출물을 자신의 시스템에 연결한다. 의현의 완료 기준은 외부 시스템 통합이 아니라 각 모듈이 독립 테스트를 통과하는 것이다.

## 3. 작업 순서

### 1단계. 플레이어 기반 구조

- Input System 액션 정의
- 플레이어 상태 정의: 정상, 대시, 피격, 사망
- 이동, 전투, 능력치, 시각 표현의 책임 분리
- 테스트 씬과 임시 바닥·벽 준비

완료 조건:

- 테스트 씬에서 플레이어가 생성된다.
- 입력과 플레이어 로직이 한 스크립트에 과도하게 결합되지 않는다.

### 2단계. 이동과 카메라

- WASD 이동
- 회전 또는 바라보는 방향 처리
- Space 대시
- 대시 횟수 및 쿨타임
- 벽·구조물 충돌
- 고정 카메라 추적

완료 조건:

- 이동과 대시가 프레임률에 영향받지 않는다.
- 벽을 통과하거나 대시 후 조작이 잠기는 문제가 없다.
- 카메라가 전투 가독성을 유지한다.

### 3단계. 플레이어 능력치와 생존

- 기본 능력치 데이터 정의
- 최대 HP와 현재 HP
- 공격력, 공격 속도, 이동 속도
- 쿨타임과 대시 관련 수치
- 피격, 무적 시간 후보, 사망
- 플레이어 내부 능력치 변경 및 초기화

완료 조건:

- 디버그 UI에서 능력치를 바꾸면 즉시 플레이에 반영된다.
- 디버그 값으로 능력치별 플레이 변화를 시험할 수 있다.

### 4단계. 기본 공격과 조준

- 기본 자동 조준
- 좌클릭 시 수동 조준
- 공격 속도에 따른 공격 주기
- 공격 범위 및 피해량 적용
- 공격 대상이 없을 때의 동작 정의
- 근접·투사체 공격이 공통으로 사용할 공격 요청 구조 마련

완료 조건:

- 자동 조준과 수동 조준이 서로 충돌하지 않는다.
- 능력치 변경이 공격력과 공격 속도에 반영된다.
- 임시 타깃을 공격해 피해를 줄 수 있다.

### 5단계. 전사 액티브 스킬

- 검기 날리기
- 입력, 쿨타임, 시전, 피해 판정
- 스킬 사용 불가 상태 처리
- 스킬 데이터와 실행 로직 분리
- 속성 효과를 나중에 주입할 확장 지점 제공

완료 조건:

- 이동, 기본 공격, 대시와 함께 자연스럽게 사용할 수 있다.
- 쿨타임 변경이 즉시 반영된다.
- 불/물 등의 실제 속성 구현 없이도 효과 Hook을 호출할 수 있다.

### 6단계. 공통 시드 서비스

- 런 시드 생성 및 직접 입력
- 현재 런 시드 보관
- 시스템별 파생 시드 생성
- 이름이 지정된 독립 난수 스트림 제공
- 정수, 실수, 확률, 셔플, 가중치 선택 API
- Unity 전역 `Random`과 분리

권장 스트림 예시:

```text
RunSeed
├─ Map
├─ Monster
├─ Item
├─ Shop
└─ Event
```

한 스트림의 난수 호출 횟수가 다른 스트림의 결과를 바꾸지 않도록 독립시킨다. 실제 맵·몬스터·아이템 코드에 이 스트림을 연결하는 작업은 각 담당자가 수행한다.

완료 조건:

- 같은 런 시드와 스트림 이름은 항상 같은 결과를 만든다.
- 한 스트림의 호출 횟수가 다른 스트림 결과에 영향을 주지 않는다.
- 공개된 시드 API 자체가 독립 테스트를 통과한다.

### 7단계. 시드 디버그와 검증

- 현재 시드 표시
- 시드 복사 및 직접 입력
- 스트림별 호출 결과 확인
- 같은 시드 재실행
- 개발 빌드에서만 사용하는 간단한 검증 UI
- 재현 실패 시 어느 스트림에서 달라졌는지 확인할 로그

완료 조건:

- 같은 시드로 여러 번 실행한 결과가 일치한다.
- 버그 제보에 시드 하나만 첨부해 주요 랜덤 결과를 재현할 수 있다.

### 8단계. 플레이어 모듈 자체 검증

- 이동, 대시, 조준, 기본 공격, 스킬을 연속 사용
- 사망 후 플레이어 상태 초기화
- 능력치별 최소·최대 테스트
- 프레임률 변화에 따른 이동과 공격 결과 확인
- 플레이어 테스트 씬에서 반복 실행

완료 조건:

- 몬스터와 아이템 없이 더미 타깃과 디버그 값만으로 플레이어 기능을 검증할 수 있다.
- 테스트 씬을 반복 실행해도 상태가 남거나 입력이 잠기지 않는다.

### 9단계. 추가 직업

게임 한 사이클의 통합이 안정된 뒤 진행한다.

1. 공통 직업 기반 구조 정리
2. 궁수 기본 공격과 일제사격
3. 마법사 기본 공격과 파이어볼
4. 직업 교체 시 입력, 능력치, 스킬 정상 초기화 확인

## 4. 실제 우선 백로그

| 순서 | 의현 작업 | 결과물 |
|---:|---|---|
| 1 | 입력과 플레이어 구조 | 확장 가능한 플레이어 기반 |
| 2 | 이동, 대시, 카메라 | 조작 가능한 전사 |
| 3 | 능력치, HP, 피격, 사망 | 플레이어 생존 규칙 |
| 4 | 자동/수동 조준과 기본 공격 | 기본 전투 플레이 |
| 5 | 전사 검기 스킬 | 첫 액티브 스킬 |
| 6 | 공통 시드와 독립 스트림 | 재현 가능한 랜덤 모듈 |
| 7 | 시드 디버그 UI와 테스트 | 시드 자체 검증 수단 |
| 8 | 플레이어 모듈 자체 검증 | 독립적으로 완성된 전사 |
| 9 | 궁수와 마법사 | 플레이어블 3직업 |

## 5. 의현이 만들지 않을 테스트 기능

테스트를 위해 필요하더라도 다음 기능을 정식 구현하지 않는다.

- 방 생성 및 전환
- 노드 지도
- 몬스터 AI와 보스 패턴
- 실제 아이템과 인벤토리
- 몬스터·아이템과 플레이어 연결
- 맵·몬스터·아이템에 시드 연결
- 저장 파일과 이어하기
- 보상, 상점, 제련소, 업적

대신 최소 테스트 더블만 사용한다.

- 몬스터 대신 `DummyTarget`
- 맵 대신 바닥과 벽이 있는 `PlayerTestScene`
- 아이템 대신 능력치 Modifier 디버그 버튼
- 보스 대신 큰 HP를 가진 더미
- 실제 랜덤 콘텐츠 대신 스트림 결과 출력

## 6. 의현 담당 완료 판정

- 전사가 이동, 대시, 자동/수동 조준, 기본 공격, 검기를 사용할 수 있다.
- 능력치 변경이 모든 플레이 기능에 즉시 반영된다.
- 더미 타깃과 디버그 피격 영역만으로 공격·피격·사망을 검증할 수 있다.
- 같은 런 시드가 같은 시스템별 난수 결과를 만든다.
- 한 시스템의 난수 호출이 다른 시스템의 결과를 바꾸지 않는다.
- 시드 모듈은 실제 콘텐츠 연결 없이 독립 테스트를 통과한다.
- 전사 플레이 기능은 실제 몬스터·아이템 연결 없이 독립 테스트를 통과한다.
