# 시드 시스템 확정 설계

## 1. 기본 정책

- 난수 알고리즘: MT19937 메르센 트위스터
- 사용자 시드: 숫자 6자리
- 동일 시드는 알고리즘 버전, 콘텐츠 후보와 정렬, 난수 호출 순서가 같다면 Unity 또는 게임 업데이트 이후에도 동일한 결과 보장
- UnityEngine.Random과 System.Random의 내부 구현에 의존하지 않음
- MT19937 알고리즘, 시드 초기화, 범위 변환, 셔플, 가중치 선택 구현을 프로젝트 버전 1로 고정
- EditMode 자동 테스트로 결과 변경 감지

## 2. 시드 생명주기

```text
게임 시작 후 최초 마을 진입
→ 6자리 시드 자동 생성 및 표시
→ 필요하면 디버그 UI에서 시드 교체
→ 던전 입장 시 현재 시드를 RunSeed로 확정
→ 던전 진행 중 RunSeed 변경 금지
→ 성공/실패 후 마을 귀환
→ 다음 런을 위한 새 시드 생성
```

시드 입력란이 비어 있으면 무작위 6자리 시드를 생성한다. 디버그 입력값이 있으면 해당 값을 다음 런에 사용한다.

## 3. 순서 의존형 정책

각 스트림 안에서는 난수를 순서대로 소비하는 순서 의존형을 사용한다. 다만 런 전체가 전역 MT19937 하나를 공유하지는 않는다.

### 전역 스트림 하나를 피하는 이유

시드가 던전 도중 바뀌지 않아도 난수 호출 순서는 개발 중 바뀔 수 있다. 예를 들어 상점 담당자가 가격 변동을 위해 난수를 한 번 추가하면, 같은 전역 스트림을 쓰는 이후 맵·아이템·이벤트 결과가 모두 한 칸씩 밀린다.

### 확정 구조

RunSeed와 문자열 스트림 이름을 안정적인 해시 함수로 조합해 각 시스템의 초기 시드를 만든다. 각 스트림 내부에서는 MT19937 값을 순서대로 사용한다.

```text
RunSeed 123456
├─ Map
├─ Monster
├─ Item
├─ Shop
├─ Forge
└─ Event
```

이 구조는 순서 의존형의 단순함을 유지하면서 한 시스템의 난수 호출 추가가 다른 시스템 결과를 바꾸는 문제를 방지한다. 스트림 이름은 팀원이 필요에 따라 추가할 수 있다.

## 4. 시드 적용 대상

- 막과 지역 테마 선택
- 노드 지도 형태와 연결
- 방 종류와 배치
- 일반·엘리트·보스 방 선택
- 몬스터 종류, 등급, 수량, 스폰 위치
- 엘리트 특성 선택
- 방 구조와 환경 오브젝트 배치
- 보상 아이템 후보
- 아이템 등급, 옵션, 속성 후보
- 상점 품목과 가격 변동 후보
- 제련·강화·승급 성공 여부와 결과
- 이벤트 종류와 선택 결과
- 미지 노드 결과
- 포션 및 구조물 드롭
- 테마·방·이벤트 출현 보장 규칙
- 리롤 결과

## 5. 시드에서 제외할 대상

- 치명타
- 회피
- 화상 등 전투 중 상태 이상 부여 확률
- 공격 중 실시간 행운 판정
- 시각 효과의 장식용 무작위
- 사운드 피치 변화

전투 확률은 런 콘텐츠 재현용 시드 스트림을 소비하지 않아야 한다.

## 6. 제공할 API

의현은 난수 모듈과 아래 API, 문서, 테스트까지만 제공한다. 콘텐츠에 적용하는 작업은 각 담당자가 수행한다.

- 스트림 생성 또는 조회
- 다음 32비트 정수
- 정수 범위
- 실수 범위
- 확률 판정
- 목록 무작위 선택
- 목록 셔플
- 가중치 선택
- 스트림 상태 추출 및 복원

## 7. 업데이트 후 재현 보장 규칙

다음 항목을 변경하면 기존 시드 결과가 달라질 수 있으므로 임의 수정하지 않는다.

- MT19937 핵심 알고리즘
- 정수 시드 초기화 방식
- 문자열 스트림 이름을 정수로 바꾸는 해시
- 정수·실수 범위 변환 방식
- 셔플 알고리즘
- 가중치 선택 방식
- 콘텐츠의 난수 호출 순서
- 콘텐츠 후보 목록의 구성과 정렬 순서
- 콘텐츠를 식별하는 ID

필요한 변경이 생기면 `SeedAlgorithmVersion`을 올리고 기존 버전을 유지한다.

아이템이나 방 후보가 추가·삭제되거나 목록 순서가 바뀌면 동일한 난수가 다른 콘텐츠를 선택할 수 있다. 업데이트 후 완전한 재현이 필요하면 콘텐츠 데이터에도 버전을 부여하고, 구 버전 후보 목록을 유지해야 한다.

## 8. EditMode 자동 테스트

- MT19937 공식 기준 출력과 일치
- 동일 시드·동일 스트림의 결과 일치
- 다른 시드의 결과 차이
- 서로 다른 스트림의 독립성
- 한 스트림의 추가 호출이 다른 스트림에 영향을 주지 않음
- 정수와 실수의 범위 끝값 규칙
- 셔플 결과 재현
- 가중치 0인 후보 제외
- 상태 추출 후 복원 결과 일치
- 알고리즘 버전 1의 고정 회귀 결과

팀 공통 기준 시드는 `123456`으로 사용한다.
