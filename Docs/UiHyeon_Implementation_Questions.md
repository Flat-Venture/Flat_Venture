# 의현 담당 구현 전 질문지

> 대상 범위: 플레이어 플레이 기능, 공통 시드 모듈  
> 현재 확인된 상태: Unity 6000.3.18f1, URP 17.3, Input System 1.19, 플레이어 코드 없음, 기본 SampleScene만 존재

아래 질문은 번호를 유지한 채 답변하면 된다. 아직 정하지 못한 항목은 `미정`이라고 답해도 되며, 그 경우 프로토타입 기본값으로 진행한다.

## A. 구현 시작 전에 반드시 필요한 답변

### 1. 목표 플랫폼

- 첫 출시 또는 테스트 대상은 Windows PC 단독인가?
- 키보드·마우스만 우선 지원하면 되는가?
- 게임패드 지원을 지금 포함할지, 나중으로 미룰지?

### 2. 게임 시점과 좌표계

- 카메라는 탑다운, 쿼터뷰, 아이소메트릭 중 어느 느낌인가?
- 카메라 각도와 거리의 참고 게임 또는 참고 이미지가 있는가?
- 플레이어는 3D 바닥의 XZ 평면에서만 이동하는가?
- 점프와 높낮이 이동은 완전히 없는가?

### 3. 플레이어 표현 방식

- 기획안의 `플레이어 = Sprite`를 그대로 사용할 것인가, 임시 3D 캡슐로 시작할 것인가?
- Sprite라면 항상 카메라를 바라보는 빌보드 방식인가?
- 이동 방향에 따라 좌우 반전만 하는가, 4방향 또는 8방향 애니메이션인가?
- 현재 사용할 캐릭터 Sprite, 애니메이션, 이펙트 에셋이 있는가?

### 4. 이동 방식

- 이동은 즉시 최고 속도가 되는 방식인가, 가속·감속이 있는 방식인가?
- 대각선 이동 속도는 정규화해 직선과 같게 할 것인가?
- 이동 중 캐릭터가 바라볼 방향은 이동 방향인가, 조준 방향인가?
- 플레이어 이동에 Rigidbody, CharacterController 중 선호가 있는가? 없다면 구현에 맞게 선택해도 되는가?
- 플레이어가 적이나 다른 플레이어를 물리적으로 밀 수 있어야 하는가?

### 5. 대시 규칙

- 대시 방향은 현재 이동 입력 방향인가, 조준 방향인가?
- 이동 입력이 없을 때 대시하면 마지막 이동 방향으로 가는가, 사용되지 않는가?
- 대시 거리 또는 지속 시간은 어느 정도가 좋은가?
- 대시 도중 무적인가? 무적이라면 전체 시간인가, 일부 구간인가?
- 대시 중 방향 전환과 공격·스킬 사용이 가능한가?
- 대시가 벽에 닿으면 즉시 멈추는가?
- 기본 대시 횟수와 충전 방식은 무엇인가?
- 대시 입력은 기획안대로 Space인가?

### 6. 기본 공격의 정확한 조작

- 기본 공격은 자동으로 계속 발동하는가, 공격 키를 누르고 있을 때만 발동하는가?
- 자동 조준은 가장 가까운 적을 선택하는가?
- 자동 조준 탐색 범위와 화면 밖 적 조준 허용 여부는?
- 좌클릭은 공격 자체를 발동하는가, 자동 공격의 조준 방향만 바꾸는가?
- 좌클릭 수동 조준은 마우스 위치 방향인가, 클릭한 적을 고정 타깃으로 삼는가?
- 수동 조준 상태는 클릭하는 순간만 유지하는가, 일정 시간 유지하는가?
- 전사의 기본 공격은 근접 검 공격인가, 원거리 검기인가?
- 공격 중 이동 가능한가? 가능하다면 이동 속도 감소가 있는가?
- 공격 시 캐릭터가 조준 방향으로 자동 회전하는가?

### 7. 전사 액티브 스킬

- 검기 날리기는 어느 키로 사용하는가?
- 검기는 직선 투사체인가, 부채꼴인가, 넓은 관통 파동인가?
- 적을 관통하는가? 최대 적중 수가 있는가?
- 벽과 충돌하면 사라지는가?
- 시전 시간, 후딜레이, 기본 쿨타임의 원하는 감각은?
- 스킬 사용 중 이동과 대시가 가능한가?
- 스킬에 애니메이션 취소 규칙이 필요한가?
- 첫 구현부터 불·물 속성 효과를 넣는가, 검기 자체만 먼저 만드는가?

### 8. 플레이어 생존 규칙

- 플레이어 기본 HP는 얼마인가?
- 피격 직후 무적 시간이 있는가? 있다면 몇 초인가?
- 피격 시 넉백, 경직, 화면 흔들림이 필요한가?
- HP가 0이면 즉시 사망하는가, 다운 상태가 있는가?
- 사망 후 플레이어 모듈은 어떤 상태까지만 처리하면 되는가? 예: 입력 정지와 사망 이벤트 발생
- 낙사나 맵 밖 이탈 처리가 필요한가?

### 9. 능력치의 1차 구현 범위

첫 플레이어 버전에 반드시 동작해야 할 능력치를 골라야 한다.

- 공격력
- 주문력
- 최대 HP
- 받는 피해 감소
- 회피율
- 기본 공격 속도
- 이동 속도
- 치명타 확률과 치명타 피해
- 액티브 스킬 쿨타임
- 대시 쿨타임과 대시 횟수
- 투사체 수·속도·크기
- 공격 및 스킬 범위
- 시전 속도
- 보호막, 생명력 흡수, 주는 피해 증가

추가 질문:

- 능력치는 정수와 실수 중 어떤 표시 방식을 원하는가?
- 공격 속도·쿨타임 감소 등에 상한과 하한이 필요한가?
- 피해 계산식을 이미 정했는가?
- 치명타, 회피, 피해 감소의 계산 순서를 정했는가?

### 10. 일시정지와 입력 차단

- ESC 일시정지가 필요한가?
- 일시정지 시 `Time.timeScale = 0` 방식으로 전체 시간을 멈춰도 되는가?
- UI가 열렸을 때 이동·공격 입력은 모두 막는가?
- 키 설정 변경 기능은 이번 범위인가, 나중 범위인가?

## B. 시드 모듈 구현 전에 반드시 필요한 답변

### 11. 시드의 형태

- 사용자에게 보여줄 시드는 숫자만 사용하는가, 문자열도 허용하는가?
- 시드를 사용자가 직접 입력할 수 있어야 하는가?
- 시드가 비어 있으면 무작위로 생성하면 되는가?
- 시드 표시·복사 UI는 의현이 만드는가, 모듈 API만 제공하는가?

### 12. 재현 범위

- 같은 시드는 Unity 버전이나 게임 업데이트 후에도 영구적으로 같은 결과를 보장해야 하는가?
- 같은 게임 빌드 안에서만 재현되면 충분한가?
- 난수 결과가 게임 프레임 수나 호출 타이밍과 무관해야 하는가?
- 시드 알고리즘 버전을 저장할 필요가 있는가?

### 13. 난수 스트림 정책

- 스트림 이름은 우선 `Map`, `Monster`, `Item`, `Shop`, `Event`로 두면 되는가?
- 각 담당자가 임의의 스트림 이름을 만들 수 있게 할 것인가?
- 같은 스트림을 여러 객체가 공유하는가, 방·층·노드별 하위 스트림도 필요한가?
- 순서 의존형 난수와 키 기반 결정형 난수 중 어느 사용 방식이 필요한가?

예시:

```text
순서 의존형: Monster 스트림에서 다음 정수를 차례로 뽑음
키 기반: (RunSeed, StageId, RoomId, SpawnIndex)로 결과를 직접 계산
```

### 14. 시드 모듈의 책임 경계

- 의현은 난수 API만 제공하고 각 콘텐츠 연결은 담당자가 하는 것으로 확정하면 되는가?
- 필요한 기본 API는 다음 정도면 충분한가?
  - 정수 범위
  - 실수 범위
  - 확률 판정
  - 리스트 셔플
  - 리스트 무작위 선택
  - 가중치 선택
- 난수 스트림의 현재 상태 저장/복원은 세이브 담당자가 구현하는가, 시드 모듈이 상태 직렬화 API까지 제공해야 하는가?

### 15. 시드 테스트 기준

- EditMode 자동 테스트를 프로젝트에 추가해도 되는가?
- 동일 시드 동일 결과, 스트림 독립성, 범위·확률 API를 자동 테스트하면 충분한가?
- 테스트용 시드 고정값을 팀 공통으로 정할 것인가?

## D. 지금 답하지 않아도 되는 항목

- 모든 능력치의 최종 상한·하한
- 궁수와 마법사의 상세 공격 규칙
